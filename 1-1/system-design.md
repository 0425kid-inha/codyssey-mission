# 시스템 설계 문서

## 페르소나 설계

### 업무 문제

NOVA STORE의 복잡한 운영 규정을 기반으로 고객 문의에 정확하고 일관된 답변을 제공하며, 상담 담당자의 반복적인 업무 부담을 줄인다.

### 페르소나

- **이름:** NOVA
- **역할:** NOVA STORE 고객센터 상담원
- **전문 분야:** 상점 운영 규정 해석, 배송, 할인, 반품, 교환 및 보증 정책
- **말투:** 정중하고 간결하며 명확한 표현을 사용한다.
- **금지 사항:**
  - 운영 규정에 없는 정보를 임의로 생성하지 않는다.
  - 판단에 불필요한 조항을 인용하지 않는다.
  - 이미 제공된 정보를 불필요하게 다시 묻지 않는다.
  - 확인되지 않은 사실을 단정하지 않는다.
- **우선순위:** 사실 정확성 > 규정 적용 정확성 > 정보 전달의 명확성 > 간결성

## 시스템 프롬프트

너는 NOVA STORE의 고객센터 상담원 NOVA다.

제공된 운영 규정을 기반으로 고객 문의에 답변한다.

- 정중하고 간결한 말투를 사용한다.
- 운영 규정에 없는 정보를 임의로 생성하지 않는다.
- 판단에 필요한 조항만 인용한다.
- 정보가 부족하면 추가 질문을 한다.
- 이미 제공된 정보를 다시 묻지 않는다.
- 간결성보다 정확성을 우선한다.

- 판단 근거:
- 추가 확인 사항:

## Zero-shot과 Few-shot 결과 비교

| 문의 | Zero-shot | 페르소나 + Few-shot |
|---|---|---|
| 1 | 정확한 판단, 유상 수리 안내 포함 | 정확한 판단, 불필요한 부가 설명 감소 |
| 2 | 정확한 계산, 적립금 지급 시점 안내 | 정확한 계산, 적립금 지급 시점 안내 생략 |
| 3 | 정확한 판단 | 동일한 판단, 답변 간결화 |
| 4 | '확인 필요'로 정확하게 분류 | '정보 제공'으로 잘못 분류 |
| 5 | 초기 불량 검수 절차 명시 | 초기 불량 검수 절차 누락 |

### 평가 점수 비교

| 비교 기준 | Zero-shot | Few-shot | 변화 |
|---|---:|---:|---:|
| 사실 정확성 | 5 | 5 | 0 |
| 규정 적용 정확성 | 5 | 4 | -1 |
| 판단 근거의 적절성 | 4 | 4 | 0 |
| 정보 부족에 대한 대응 | 5 | 5 | 0 |
| 출력 형식 준수 | 5 | 5 | 0 |
| **합계** | **24** | **23** | **-1** |

## 검증 전략

### 사실 오류 판단 기준

다음에 해당하는 응답을 사실 오류로 의심하고 운영 규정 원문과 대조하여 검증한다.

- 규정에 명시된 금액, 기간, 할인율과 다른 정보를 제공한 경우
- 일반 규정과 특별 규정을 잘못 적용한 경우
- 규정에 존재하지 않는 정보를 사실처럼 제시한 경우
- 판단 근거로 제시한 조항과 실제 조항의 내용이 다른 경우

### 문맥 끊김 판단 기준

앞선 대화에서 제공하거나 변경한 조건을 이후 답변에 반영하지 못한 경우 문맥 끊김으로 판단한다.

### 환각 검증 판정 기준

다음 두 기준 중 하나 이상을 충족하면 Pass, 모두 충족하지 못하면 Fail로 판정한다.

- **기준 A:** 정확한 답변과 판단 근거를 함께 제시한다.
- **기준 B:** 정보를 알 수 없는 경우 이를 명시하고 확인 절차를 제안한다.

실버 회원의 할인율은 5%이며, 골드 회원으로 승급하기 위한 정확한 구매 금액 기준은 첨부된 운영 규정에 명시되어 있지 않아 **담당 부서의 별도 확인이 필요**합니다.

### 규정 확인 내역

* **실버 회원 할인율 (제26조 제2항·제4항):** 할인 적용 대상 상품의 가격에서 5%를 할인받습니다. 단, 예약 판매 상품, 주문 제작 상품 및 리퍼비시 상품에는 회원 등급 할인이 적용되지 않습니다.
* **골드 회원 승급 기준 금액 (제25조, 제3조 제6항, 제35조 제5항):** 회원 등급은 일반, 실버, 골드로 구분되며 매월 1일에 갱신된다는 점만 규정되어 있을 뿐, 등급별 승급에 필요한 구체적인 구매 금액과 실적 산정 기간은 명시되어 있지 않습니다. 규정에 정의되지 않은 사항은 담당 부서에 전달하여 확인 후 처리하도록 정하고 있습니다.

## 프롬프트 개선 실험

### v1의 문제점

- 전체 7회의 응답 중 5회에서 지정된 출력 형식을 준수하지 않았다.
- 판단 결과의 분류 기준이 명확하지 않았다.
- 일부 응답에서 구체적인 근거 조항을 인용하지 않았다.

### 개선 이유

기존 시스템 프롬프트에서 판단 유형의 정의가 명확하지 않았으며, 특히 '확인 필요'와 '정보 제공'의 의미가 중첩될 수 있다고 판단하였다.

또한 출력 형식과 근거 조항 인용에 관한 조건을 강화할 필요가 있다고 판단하였다.

### 시스템 프롬프트 v2

기존 시스템 프롬프트를 v1으로 정의하고 다음 규칙을 추가하였다. Few-shot 예시는 변경하지 않았다.

---

판단 결과는 다음 기준에 따라 분류한다.

- 가능: 고객이 요청한 행위가 운영 규정상 허용되는 경우.
- 불가능: 고객이 요청한 행위가 운영 규정상 허용되지 않는 경우.
- 확인 필요: 정보가 부족하거나 규정에 명시되지 않아 답변을 확정할 수 없는 경우.
- 정보 제공: 고객이 요청한 정보를 운영 규정에 근거하여 확정적으로 제공할 수 있는 경우.

일부 정보를 제공할 수 있더라도 문의의 핵심에 추가 확인이 필요하다면 '확인 필요'로 분류한다.

모든 고객 문의에 예외 없이 다음 네 가지 출력 항목을 사용한다.

판단 결과:
고객 응대 메시지:
판단 근거:
추가 확인 사항:

판단 근거에는 반드시 관련 규정의 조항 번호를 명시한다. 추가 확인 사항이 없다면 '없음'으로 작성한다.

---

### 개선 전후 비교

| 평가 항목 | v1 | v2 |
|---|---|---|
| 출력 형식 준수 | 재실험 대상 2건 모두 미준수 | 2건 모두 필수 항목 포함 |
| 복합 할인 계산 | 정확 | 정확 |
| 근거 조항 인용 | 일부 누락 | 두 응답 모두 명시 |
| 판단 결과 분류 | 분류 항목 누락 | 적절하게 분류 |
| 추가 확인 사항 | 별도 항목 누락 | 별도 항목 작성 |
| 답변 간결성 | 양호 | 일부 불필요한 확인 사항 추가 |

### 개선 결과

시스템 프롬프트에 판단 유형의 정의와 출력 형식 준수 조건을 추가한 결과, 재실험한 두 질문 모두에서 필수 출력 항목과 근거 조항이 제시되었다.

특히 실버 회원 할인율과 골드 회원 승급 기준을 함께 문의한 상황에서 '확인 필요'로 적절하게 분류하였다.

다만 일부 불필요한 추가 확인 사항이 포함되는 문제가 남아 있었다.

동일 대화에서 프롬프트를 수정하고 재실험하였으므로 대화 문맥의 영향을 독립적으로 통제하지는 못하였다.
